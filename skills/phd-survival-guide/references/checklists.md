# Checklists

From the New Researcher Handbook. Use these to review someone's work: go item by item, mark what's missing, and give the most important fixes first.

## Presentation
- [ ] Title slide has title, name, date, affiliation
- [ ] Outline matches the actual content
- [ ] Every figure has labeled axes and a descriptive caption
- [ ] Experimental setup is explained before results
- [ ] Results are connected to the hypotheses
- [ ] One message per slide; no walls of text (6×6 rule)
- [ ] Fonts readable from the back (≥ 24pt body, ≥ 32pt titles)
- [ ] Acknowledgments included
- [ ] Rehearsed and within the time limit
- [ ] Slides numbered; references cited

## Figure
- [ ] Title says what is shown
- [ ] X-axis and Y-axis labeled, with units
- [ ] Legend explains all symbols and colors
- [ ] Font size readable when projected
- [ ] Accessible color scheme (e.g., Okabe-Ito, Viridis); no red–green pairs
- [ ] Same model, same color and order across subplots
- [ ] Error bars or confidence intervals shown
- [ ] Caption explains the key finding
- [ ] Vector format (PDF/SVG) where possible

## Reproducibility (before publishing)
- [ ] Environment file (`environment.yml` or `requirements.txt`)
- [ ] Random seeds set for all stochastic processes
- [ ] Data availability statement with download links or instructions
- [ ] README with step-by-step reproduction instructions
- [ ] Versions of major dependencies recorded
- [ ] Hardware documented (GPU, RAM)
- [ ] Expected outputs included for verification
- [ ] Dockerfile for complex environments
- [ ] Notebooks cleared and run top to bottom
- [ ] Tests for key functions

## Server setup
- [ ] SSH keys for passwordless login
- [ ] tmux/screen session for persistent work
- [ ] Conda environment set up and activated
- [ ] Data in the right directory (scratch/data, not home)
- [ ] Job script tested on a small dataset
- [ ] Resource needs estimated
- [ ] Log/output directory created
- [ ] Backup of important results

## Research idea quick validation
- [ ] Discussed with 3+ people
- [ ] One-sentence explanation ready
- [ ] Checked the last 2 years of conferences
- [ ] Necessary resources available
- [ ] Can prototype in 2 weeks
- [ ] Rated on FIVE+C; no red flags (too incremental, too ambitious, already solved, no metric, unavailable resources)

## Technical paper, before writing
- [ ] Contribution fits in one sentence
- [ ] Clear experimental validation plan (must-have comparisons vs. supporting ablations)
- [ ] Checked papers from the last 6 months for novelty
- [ ] Framing fits the venue's current trends
- [ ] Backup venue if rejected

## Survey paper
- [ ] Comprehensive coverage with clear categories
- [ ] An organizing framework for the field
- [ ] Critical analysis of gaps and limitations
- [ ] Future directions identified
- [ ] Tables and figures that stand on their own
- [ ] Papers from the last 6–12 months included
- [ ] Clear definitions and taxonomy

## Advisor meeting prep
- [ ] Short written summary of progress
- [ ] Visual evidence (plots, tables, diagrams)
- [ ] Specific questions ranked by priority
- [ ] Your proposed solutions to current challenges
- [ ] Concrete plan for the next period

## Weekly update
- [ ] Progress: what was done
- [ ] Challenges, stated honestly
- [ ] Plans for next week
- [ ] Questions and help needed
- [ ] 5–10 slides with visual evidence
